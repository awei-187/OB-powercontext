# 技术说明：SDD 工程上下文模块

本作品通过一个订单查询修改任务验证规格驱动开发闭环：增加状态筛选，先过滤后分页，保留原有行为。
CLI 是应用入口；不依赖界面。当前有效业务规则在 `specs/orders-v1.md`，导入范围在 `project.json`。

## 三项技术的作用

- **seekdb**：保存真实规格、实现、测试正文及其 SHA-256。当前资料与历史版本分开保存；
  每次导入完整验证文件后原子替换当前集合。按资料角色执行原生全文查询，返回原文、路径、行号、符号和规格条目。
  项目过滤在 SQL 内执行。不使用硬编码答案或隐式扫描凭据目录。
- **PowerContext**：固定官方 1.2.0 提交，使用内置 SQLite Runtime 的显式 Memory API。
  每个项目/任务通过稳定幂等键取得 Scope；保存用 remember，更新用 revise，恢复用 list/get。
  保留精确 citation，在新的 prepare 进程中与 seekdb 资料共同形成上下文。
- **MiniMax**：通过官方 mmx CLI 的中国区文本接口接收实际上下文，生成完整实现文件。
  只允许候选目标为 `sample_project/orders.py`。保留最终文本、模型标识、用量和补丁；不保存模型私有推理。

## 正确性与证据

修改前保存源文件摘要、原有功能通过和新增功能失败的日志。模型输出先在临时工作副本中运行原始目标测试和回归测试，
通过后才应用原始输出，避免覆盖并发改动。修改后再次执行同一组测试并核对摘要，将结果写入 PowerContext，更新 seekdb 当前实现。
每次调用产生独立 evidence 目录，区分失败尝试和成功运行，不把测试夹具标记当作真实业务成果。

`verify_context.py` 验证入库、引用、规格更新、命名空间与原子拒绝；`verify_task_memory.py` 使用独立进程验证持久化复用。
`replay_evidence.py` 在临时目录中复验提交的前后快照，使用 `python -S` 排除 site-packages，不调用模型，
不要求评审重新生成相同补丁。完整上下文流程需要真实 seekdb 和已安装的 PowerContext。

## 限制

目前按完整小文件检索，采用关键词相关度，不承诺跨语言语义匹配；上下文大小和单条状态有明确上限。
本地单用户运行，Scope 提供数据分区而非外部访问控制。模型原样候选仍需审阅；临时工作副本不是安全沙箱。
新的付费生成需有效 MiniMax Plan；现有开发记录和离线复验无需模型凭据。
