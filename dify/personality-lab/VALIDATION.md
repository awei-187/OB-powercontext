# 真实验证样例

本样例验证 Dify 负责生成、PowerContext 保存与召回真实选择，而不是只检查 YAML 或使用 mock。

## 前置条件

1. PowerContext `1.5.0` 已启动，`Status-PowerContext.ps1` 的 `live` 和 `ready` 均成功。
2. Dify `1.19.0` 中已导入、绑定模型并发布 `workflow/personal-manual.yml`。
3. `.env` 设置 `PROFILE_MODE=dify`、本应用专用 `DIFY_API_KEY` 和 `POWERCONTEXT_URL=http://127.0.0.1:8000`。
4. 应用运行于 <http://127.0.0.1:8790/>。
5. 使用新的浏览器隐私窗口，或在旧报告页点击“再测一次”并确认重新开始。

## 固定操作样例

1. 点击“开始测试”，等待“正在准备场景……”结束。
2. 自我预判依次选择：做事节奏左侧、协作方式中间、面对未知右侧；点击“选好了，开始答题”。
3. Q1—Q6 均选择 C。
4. 两个“换个条件”页面依次选择 B、C。
5. “只能留下两样”第一步选择 A 和 C，第二步选择 C 作为全程保留。
6. “替别人选一次”给自己选择 A，给小周选择 C。
7. 点击“查看我的说明书”，等待生成完成。

## 预期结果

- 开始阶段出现六个完整故事，每题四个选项；页面运行信息显示 `Dify 工作流`。
- 每次提交后进入下一阶段，刷新页面能够恢复进度。
- 最终状态包含 6 项初选、2 项反转、2 项取舍、2 项换位，以及开始前的 3 项预判。
- 应用保存 15 份写入回执，其中 `source_id` 与 Atomic Memory Artifact ID 各 15 个且均唯一；PowerContext 库存会显示 30 个 Source，因为每项同时经过 content 与 remember 两条写入路径。
- 报告前 `pendingMemory=0`；召回核对覆盖 P1—P3、Q1—Q6、R1—R2、T1—T2、S1—S2。
- 报告包含三个倾向条、摘要、建议、三条有效初选证据、两条反转对照，以及预判／取舍／换位对照。
- 页脚显示 `Dify 生成档案 · 已核对 PowerContext 初选与反转记录`。
- 可以导出 JSON、SVG 长卡片，或使用浏览器打印为 PDF。

## 故障行为

- Dify 题集两次都不合格：页面明确提示本局使用固定题库，不把它称为 Dify 新题。
- PowerContext 写入失败：选择先保存在本机，页面提供“重试记忆同步”；报告保持阻断。
- PowerContext 召回不全、跨 Scope 或原文不一致：返回 503，选择仍保留。
- Dify 报告不合格：返回 502，仍停留在可重试的报告准备页。

## 本机已完成证据

2026-11-08 的脱敏真实运行记录位于 `evidence/`，汇总见 `FINAL_ACCEPTANCE.md`。这些文件只保存版本、计数、状态和哈希，不含 API Key、Cookie、完整选择文本或人格报告正文。

本验证只证明同一轮在退出重进或服务重启后可以恢复。点击“重新开始”会创建新测试和新 Scope；当前版本不会自动把上一轮内容召回到新一轮。
